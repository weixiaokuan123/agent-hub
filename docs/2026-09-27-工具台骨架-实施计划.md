> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 `agent-hub` 里挂一个 `/tool` 页面和一个 `/tool/api/*` 后端面，把 `myuseofminerU` 的现成 CLI 接通，跑通「浏览器 → agent-hub → Python CLI → JSON 回显」这条最长的链路。

**Architecture:** 不新建服务、不新建框架。`agent-hub` 已有 HTTP 服务（端口 39310，回环绑定，hub-key 鉴权）；我们**只追加**两类东西：① 一条 `GET /tool` 路由，吐出独立的单文件 HTML；② 一组 `/tool/api/*` 路由，用 `node:child_process` 调 Python CLI，解析其 stdout JSON 后回传。`/api/*` 下现有的签到面板逻辑一行不动。

**Tech Stack:** Node 24（原生跑 `.ts`，无构建、无 npm 依赖）+ `node:child_process.spawn` + `node:test`；Python 3.14（`py -3.14`）+ `myuseofminerU/cli.py`；前端单文件 HTML + 内联 CSS/JS。

## Global Constraints

- **目标仓库**：`C:\Users\SomeUser\.config\opencode\agent-hub`（下称「仓库根」）。它**没有** `package.json`，零依赖，Node 24 原生跑 TS。**不要**引入 npm 包，**不要**建 `package.json`。
- **端口固定 39310**，仅绑 `127.0.0.1`。`HOST` 常量已存在（`server.ts:31`）。
- **CSP 极严**（`server.ts:629-638`）：`default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; connect-src 'self'`。工具台 HTML **必须**是单文件内联 script/style，**禁止**任何 CDN、外部字体、外部图片、外链 JS/CSS。所有 `fetch` 只能打回 `'self'`（同源 39310）。
- **鉴权**：`/tool/api/*` **必须**走现有 `authed(req)`（`server.ts:606`），`Authorization: Bearer <hub-key>`。key 由 `loadOrCreateHubKey()`（`server.ts:130`）管理，存 `keys/hub.key`。前端从 `localStorage['agent-hub-key']` 读取（与现有面板一致，见 `public/index.html:295`）。
- **Origin / Host 检查**：`handle()`（`server.ts:678-679`）已对**所有**请求做回环校验，新路由自动继承，不要绕过。
- **响应安全头**：`applySecurityHeaders(res)`（`server.ts:646`）已包裹 `res.writeHead`，新路由**不要**手动加安全头，也不要绕过这个包装。
- **请求体上限**：`BODY_LIMIT = 1024 * 1024`（1 MB，`server.ts:797`）。工具台的 POST 不要设计成需要传大体积 body 的形态（传路径，不传文件内容）。

- **Python CLI 的 cwd 必须是 `D:\Software\my_pdfedit\myuseofminerU`**。`cli.py` 用的是相对 import（`from api_client import ...`、`import cli_controller`），在别的目录跑会 `ModuleNotFoundError`。
- **不动的东西**：`public/index.html`（签到面板）、`src/updater.ts`、`/api/*` 全部现有路由、`scripts/harden-acl.ps1`。

**修改文件**：

| 文件 | 改动 |
|---|---|
| `src/server.ts` | ① 加 `GET /tool` 分支（紧邻现有 `/` 分支）② 加模块级 `toolRouter` 变量与 `serveTool()` ③ 在 `handle()` 的鉴权后委托给 `toolRouter`。**仅追加，不改现有分支** |

**设计要点**：

- `tool-runner.ts` 与 `tool-api.ts` 分开，是因为**前者可以纯单测**（给定 stdout/stderr/退出码 → 期望的结构化结果），后者只是 HTTP 薄封装。
- `tool-api.ts` 的 `runCli` 做成**可注入依赖**，这样路由层测试不必真的 spawn Python（否则测试会依赖本机装了 `py -3.14`，还要等几秒）。
- `public/tool.html` 与 `public/index.html` 分开，不合并——签到面板格式在变，工具台也在变，混在一个文件里两边都会难受。
- Python 调用的路径与解释器**不硬编码在多个地方**，集中在 `tool-runner.ts` 顶部常量。

## Review Focus

以下几类是设计文档的沉默处、但使用者一定会遇到的情况，每个都在对应任务的测试里钉住：

1. **Python 进程不存在 / 解释器损坏**：`py -3.14` 若不可用，或 cwd 不存在。使用者期望看到一个能读懂的错误，而不是挂起或 500 空白。→ Task 1 的 `child.on('error')` 分支覆盖。
2. **CLI 输出非 JSON**：参数错（退出码 2）时 stdout 是**空的**，错误在 stderr。若代码假设「有退出码就一定有 JSON」，会在最常见的错误路径上崩。→ Task 1 测试钉住。
3. **CLI 输出被日志污染**：stdout 前面混进了 `print` 调试行，`JSON.parse` 会直接抛。→ Task 1 测试钉住（提取首个 `{` 到末个 `}` 的策略）。
4. **长时间运行无输出**：`process` 真实跑起来可能很久，且中途不产出。使用者期望界面有反馈，且能知道进程还活着。→ Task 5 钉住（超时 + 状态）。
5. **请求体超 1 MB**：`BODY_LIMIT` 会拒绝。工具台若设计成「上传 PDF 内容」就会撞墙。→ 本计划**从设计上规避**：所有接口只收**路径字符串**，不收文件内容。
6. **鉴权被绕过**：`/tool/api/*` 若挂在鉴权之前，任何本机进程都能调用它去烧 API 额度。→ Task 3 有一条静态检查测试钉住「委托必须在 `if (!authed(req))` 之后」。
